# 00 定位与阅读方法

## 先把 Harness 放回 Agent 里

DeepSeek Harness 官方页面用一句话点清了它的位置。Agent 等于 Model 加 Harness。这里的 Model 指负责理解输入、生成文本和决定下一步的模型。Harness 负责把模型放进一个真实环境，让它能够读取信息、调用工具、维护会话、接受人的反馈，并在多轮操作中留下可追踪的记录。

这句话解决了一个常见误会。调用一次模型接口，得到一段文本，和运行一个能处理代码任务的 Agent，所需要的东西差很多。后者至少要处理环境权限、工具参数、工具结果、上下文历史、异常恢复和停止条件。Harness 把这些工作组织成可以替换的运行组件。

## dsh 是什么

dsh 是 DeepSeek Harness 的命令行入口和运行产品。官方开源仓库把它描述为开源 agent harness，底层由 Cordis 驱动。它提供 Web、headless 等运行方式，也提供让开发者扩展模型、工具、会话、执行环境和 UI 的包。

dsh 不是一个单独的模型，也不是一组固定提示词。运行时的能力来自一棵插件树。配置文件决定哪些插件被装入、以什么顺序组合，以及哪些配置行可以被上层覆盖。

## 一切皆插件意味着什么

官方页面把模型、工具、技能、会话、沙箱、存储、循环、调度和 UI 都列为插件能力。这个设计带来三个直接结果。

- 换模型时，消费模型能力的 Agent 循环可以保持不变。
- 换执行环境时，Shell、终端和文件能力可以通过 provider 替换。
- 改变一个会话的能力集合时，可以调整配置或 preset，不必先改动主循环。

插件之间通过 Cordis 的服务和事件协作。插件加载时注册服务，卸载时撤销注册产生的效果。这个生命周期让扩展行为有机会被清理，也让同一套能力能够组合到不同运行模式。

~~~mermaid
flowchart LR
  Model["模型"] --> Agent["Agent 循环"]
  Agent --> Tools["工具与环境"]
  Agent --> Memory["会话与持久化"]
  Agent --> Human["人类反馈与审批"]
  Tools --> Agent
  Memory --> Agent
  Human --> Agent
  Kernel["Cordis 插件系统"] --> Agent
  Kernel --> Tools
  Kernel --> Memory
  Kernel --> Human
~~~

## 这份教程怎样使用

建议先读 01 章把环境和命令跑通，再读 02、03 章建立架构和循环的整体图。04 到 06 章按能力、编排、数据平面展开。07 章适合准备写插件的人，08 章用来判断版本风险和验证边界。

阅读源码时，先回答两个问题。当前行为由哪个包拥有，这个包通过哪个 ctx 服务或事件暴露能力。只在文件名里搜索关键词，容易把接口、实现和模型侧工具混在一起。
