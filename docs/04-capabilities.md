# 04 能力系统

## 能力接缝比功能列表更重要

dsh 的能力很多，文件系统、Shell、终端、Web、MCP、技能、LLM 和沙箱都可以单独阅读。学习时更值得先记住它们共同遵守的结构。

- Definition 说清服务能做什么。
- Provider 负责具体实现。
- Consumer 使用服务，必要时把能力暴露给模型。

同一个接口背后可以挂不同的 provider。换执行环境、换模型提供方，Agent 循环都不需要跟着复制一份，这是接缝最直接的好处。

## LLM 能力

LLM 包负责消息和流的共同词汇，并提供适配器接缝。适配器把 dsh 内部的消息、工具 schema 和流式分片转换成具体模型服务的请求与响应。

读 LLM 相关代码时，可以按这条路径走。

1. 先看 Message、ContentBlock 和 StreamChunk 等公共词汇。
2. 再看 LlmAdapter 怎样承接模型请求。
3. 最后看 DeepSeek provider 怎样注册路由和计量能力。

本文不把某个 provider 的字段当成所有模型都必须具备的字段。模型接口会变化，精确类型应以当前源码为准。

## 执行类能力

| 能力 | 读者需要理解的边界 |
| --- | --- |
| shell | 提供 bash 或 pwsh 之类的命令执行入口 |
| subprocess | 负责启动子进程，是若干执行能力共享的底层 |
| terminal | 保持进程和终端状态，适合多轮交互 |
| code-runtime | 为代码执行提供受控运行路径 |
| sandbox | 负责约束进程和资源，降低执行风险 |
| e2b | 当前源码中用于外部执行环境的 POC 路径 |

Shell 和 subprocess 共同构成一个执行世界。终端、LSP 和文件能力面对不同的根目录时，模型会看到互相矛盾的环境。使用远程沙箱前，先确认这些 provider 指向同一个工作空间。

## 工具与数据类能力

文件系统能力让模型读取和修改文件。LSP 能够提供语义代码导航。Skill 把可复用的说明和流程装入运行时。Web 和 MCP 扩展外部信息或工具来源。Attachment 处理随会话进入的文件，spill 处理需要移出当前上下文的大块内容。

这些能力共享一个原则。模型看到的 schema、权限和结果格式都应该明确，执行动作应该经过对应的 policy 或事件。把一个脚本直接接到模型面前，会让错误、权限和审计变得难以处理。

## 组合能力时要看三件事

第一，能力作用在哪个 Agent 作用域。一个全局注册的工具和一个只属于某个 Agent 的工具，生命周期不同。

第二，能力是否会产生持久事实。工具结果如果需要恢复或回放，应进入 session event；短暂的内部状态可以留在服务实现里。

第三，能力是否需要人类确认。写文件、运行命令、访问网络和使用凭据都可能改变外部世界。审批和权限预设应该靠近执行入口，不能只靠提示词提醒模型小心。

## 一个安全的阅读顺序

先读官方架构文档里的 capability seams，再按需要打开 subsystems、package README 和 cookbook。每打开一个能力包，都找它的服务定义、provider、consumer 和测试入口。

如果你准备改动能力，先用 dsh --profile web --dump-config 确认当前运行时加载了哪一行配置。然后再判断需要改配置、加插件还是换 provider。这个顺序能减少直接改核心循环的冲动。
